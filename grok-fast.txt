### Explanation of Changes (Behavior-Focused)
The runtime `std::out_of_range` exception occurred because the absolute value calculation for `INT16_MIN` (-32768) incorrectly handled the two's complement overflow, leading to a negative magnitude value that caused out-of-bounds access in the histogram bucket array. Additionally, the bucket index calculation didn't clamp to the valid range for extreme magnitudes.

**Changes made:**
- Modified `dsp::detail::abs_i16_fast` in dsp_quantize.h to correctly return 32768 for `INT16_MIN` and changed return type to `uint16_t` for proper magnitude handling.
- Added clamping in `AudioHistogram::bucketFor` to ensure bucket indices stay within [0, buckets-1].
- Updated usages in audio_histogram.cpp to match the new return type.
- Corrected the test file path in test_audio_histogram.cpp to `"../../data/pcm_samples.txt"` for proper execution from the test working directory.
- Updated the test helper `expectedBucketSafe` to include clamping for consistency.

These minimal changes ensure robust handling of all 16-bit PCM values without altering the public API or introducing new dependencies.
