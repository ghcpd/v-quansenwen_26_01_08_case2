## What I changed (concise)
- Root cause:
  - Negating `INT16_MIN` (-32768) overflows when kept in a signed 16-bit type; this led to a negative magnitude being cast to `size_t` and producing a huge index (then later a perfect division produced an index equal to `buckets`, causing out_of_range).
- Fixes:
  1. dsp_quantize.h
     - Changed `abs_i16_fast` to return `std::uint16_t` and compute magnitude using a wider `int` before negation:
       - This correctly returns 32768 for `INT16_MIN`.
  2. audio_histogram.cpp
     - Use the unsigned magnitude returned by `abs_i16_fast`.
     - Clamp the computed bucket index to `m_counts.size() - 1` so the maximum magnitude maps to the last bucket (no out-of-range).
- Tests:
  - No test changes required; existing unit tests now pass.

## Patch (file-by-file)
- Modified: dsp_quantize.h
  - Before:
    - constexpr std::int16_t abs_i16_fast(std::int16_t x) noexcept { return (x < 0) ? -x : x; }
  - After:
    - constexpr std::uint16_t abs_i16_fast(std::int16_t x) noexcept {
        const int xi = static_cast<int>(x);
        return static_cast<std::uint16_t>((xi < 0) ? -xi : xi);
      }

- Modified: audio_histogram.cpp
  - Before:
    - const std::int16_t magnitude = dsp::detail::abs_i16_fast(sample);
    - return static_cast<std::size_t>(magnitude) / bucketWidth;
  - After:
    - const std::uint16_t magnitude = dsp::detail::abs_i16_fast(sample);
    - const std::size_t idx = static_cast<std::size_t>(magnitude) / bucketWidth;
      return std::min(idx, m_counts.size() - 1);
